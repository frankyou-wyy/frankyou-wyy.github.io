# 支路口承载多业务

‍
## 一、核心问题

```text
一个支路口 \(比如 1 个 10GE 光口\) 如何同时承载多种业务？

  ┌──────────┐
  │ 10GE 支路口│ ← 只有 1 个物理口
  │ \(1个光口\)  │
  └────┬─────┘
       │
       ├── 承载 612 个 2M 专线？
       ├── 承载 1 个 10GE 数据？
       ├── 承载 10 个 GE 数据？
       └── 承载 1 个 10GE + 若干 2M？

  答案: 通过不同的"承载方式"实现
```

---

## 二、三种技术实现方式

```text
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  方式1: 物理分路 \(最原始\)                                      │
│  ─────────────────────                                       │
│  1 个高速口 \= 物理上拆成多个低速口                               │
│  例: 1 个 10GE 口 → 通过分线器 → 10 个 GE 口                   │
│  缺点: 不灵活，带宽浪费                                         │
│                                                              │
│  方式2: 逻辑分路 \(主流\!\)                                        │
│  ─────────────────────                                       │
│  1 个高速口的带宽 \= 逻辑上划分给多个业务                          │
│  例: 1 个 10GE 口 → VLAN/优先级 → 多个业务共享                   │
│  优点: 灵活，带宽统计复用                                        │
│                                                              │
│  方式3: 映射复用 \(OTN 方式\)                                     │
│  ─────────────────────                                       │
│  1 个高速口承载的 ODUk \= 内部复用多个低阶 ODUk                    │
│  例: 1 个 ODU2 \(10G\) → 内部装 8 个 ODU0 \(8×GE\)                 │
│  优点: 标准容器，灵活调度                                        │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 三、方式1：物理分路

```text
通过物理分线器/分光器，1 个口变多个口

  ┌──────────────────────────────────────────────────────────────┐
  │                                                              │
  │  电口分路:                                                    │
  │  ─────────                                                   │
  │  1 个 10GE 电口 → 分线器 → 10 个 GE 电口                      │
  │                                                              │
  │  ┌──────┐         ┌────────┐                                │
  │  │10GE  │────────▶│ 分线器  │──▶ GE\#1 \(客户A\)                 │
  │  │电口  │         │\(物理拆分\)│──▶ GE\#2 \(客户B\)                 │
  │  └──────┘         │        │──▶ GE\#3 \(客户C\)                 │
  │                   └────────┘──▶ \.\.\.                          │
  │                                                              │
  │  光口分路:                                                    │
  │  ─────────                                                   │
  │  1 个光口 → 分光器 → 多个光口 \(功率分路\)                        │
  │                                                              │
  │  ┌──────┐         ┌────────┐                                │
  │  │光口  │────────▶│ 分光器  │──▶ 光口\#1 \(客户A, 功率降低\)       │
  │  │      │         │\(1:N\)   │──▶ 光口\#2 \(客户B, 功率降低\)       │
  │  └──────┘         └────────┘──▶ \.\.\.                          │
  │                                                              │
  │  缺点:                                                        │
  │  ├── 带宽固定分配，不灵活                                       │
  │  ├── 分光器导致功率损失                                         │
  │  └── 无法按需调整                                              │
  └──────────────────────────────────────────────────────────────┘
```

## 四、方式2：逻辑分路（PTN/IP 方式，主流）

```text
1 个物理口 \= 多个逻辑通道 \(VLAN / 优先级\)

  ┌──────────────────────────────────────────────────────────────┐
  │                                                              │
  │  1 个 GE 支路光口，同时承载:                                    │
  │                                                              │
  │  ┌──────┐         ┌──────────────────────────────────┐      │
  │  │  GE  │────────▶│ 支路盘 \(逻辑分路\)                   │      │
  │  │ 光口  │         │                                  │      │
  │  │      │         │  VLAN 100: 语音业务 \(优先级最高\)    │      │
  │  └──────┘         │  VLAN 200: 视频业务 \(优先级高\)      │      │
  │                   │  VLAN 300: 上网业务 \(优先级普通\)    │      │
  │                   │  VLAN 400: 专线业务 \(优先级保障\)    │      │
  │                   │                                  │      │
  │                   │  所有 VLAN 共享 1 个 GE 带宽       │      │
  │                   │  按优先级调度，保证关键业务          │      │
  │                   └──────────────────────────────────┘      │
  │                                                              │
  │  实现方式:                                                    │
  │  ├── VLAN 标签: 不同业务打不同 VLAN ID                         │
  │  ├── 优先级队列: 高优先级业务优先调度                            │
  │  ├── 带宽限速: 每个 VLAN 可配置最大/保证带宽                     │
  │  └── 统计复用: 所有业务共享带宽，不独占                          │
  │                                                              │
  │  示例: 1 个 GE 口 \(1000M\)                                     │
  │  ├── VLAN 100 \(语音\): 保证 100M，最大 500M                     │
  │  ├── VLAN 200 \(视频\): 保证 200M，最大 600M                     │
  │  ├── VLAN 300 \(上网\): 保证 50M，最大 1000M                     │
  │  └── VLAN 400 \(专线\): 保证 100M，最大 300M                     │
  │  → 所有业务共享 1000M，按优先级调度                              │
  └──────────────────────────────────────────────────────────────┘
```

## 五、方式3：OTN 映射复用（最常用！）

```text
1 个支路口 \= 1 个 ODUk 容器 \= 内部可装多个低阶业务

  ┌──────────────────────────────────────────────────────────────┐
  │                                                              │
  │  场景: 1 个 10GE 支路光口，要同时承载多个业务                    │
  │                                                              │
  │  ┌──────┐         ┌──────────────────────────────────┐      │
  │  │10GE  │────────▶│ 支路盘                            │      │
  │  │光口  │         │                                  │      │
  │  │\(1个\) │         │  10GE → ODU2 \(10G 容器\)           │      │
  │  └──────┘         │                                  │      │
  │                   │  ODU2 内部时隙:                    │      │
  │                   │  ┌──────┬──────┬──────┬──────┐   │      │
  │                   │  │ODU0\#1│ODU0\#2│ODU0\#3│\.\.\.\#8 │   │      │
  │                   │  │\(GE\)  │\(GE\)  │\(GE\)  │\(GE\)  │   │      │
  │                   │  └──────┴──────┴──────┴──────┘   │      │
  │                   │                                  │      │
  │                   │  8 个 ODU0 时隙 \= 8 个逻辑通道     │      │
  │                   │  每个时隙可独立调度                  │      │
  │                   └──────────────────────────────────┘      │
  │                                                              │
  │  但更常见的是: 1 个支路口 \= 1 个 ODUk \= 1 个业务               │
  │  多业务通过 多个支路口 接入，再复用到线路口                      │
  └──────────────────────────────────────────────────────────────┘
```

## 六、实际场景：一个支路口接多业务的典型方案

```text
┌──────────────────────────────────────────────────────────────┐
│                                                              │
│  方案A: 1 个高速支路口 → 拆分为多个低速业务                     │
│  ─────────────────────────────────                           │
│                                                              │
│  客户设备: 1 个 100GE 路由器                                   │
│  需要承载: 4 个 10GE 业务 \(分别去不同目的地\)                     │
│                                                              │
│  ┌──────────┐        ┌──────────────────────────────────┐   │
│  │ 100GE    │────────▶│ 支路盘                            │   │
│  │ 路由器    │        │                                  │   │
│  │ \(1个口\)  │        │  100GE → ODU4                     │   │
│  └──────────┘        │                                  │   │
│                      │  ODU4 内部拆分为:                   │   │
│                      │  ┌──────┬──────┬──────┬──────┐   │   │
│                      │  │ODU2\#1│ODU2\#2│ODU2\#3│ODU2\#4│   │   │
│                      │  │去站点A│去站点B│去站点C│去站点D│   │   │
│                      │  │\(10G\) │\(10G\) │\(10G\) │\(10G\) │   │   │
│                      │  └──────┴──────┴──────┴──────┘   │   │
│                      │                                  │   │
│                      │  交叉盘按 ODU2 级别调度:            │   │
│                      │  ODU2\#1 → 线路口\#1 \(去站点A\)       │   │
│                      │  ODU2\#2 → 线路口\#2 \(去站点B\)       │   │
│                      │  ODU2\#3 → 线路口\#3 \(去站点C\)       │   │
│                      │  ODU2\#4 → 线路口\#4 \(去站点D\)       │   │
│                      └──────────────────────────────────┘   │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  方案B: 多个低速支路口 → 复用到 1 个高速线路口                   │
│  ─────────────────────────────────                           │
│                                                              │
│  客户设备: 8 个 GE 路由器                                      │
│  需要: 8 个 GE 业务都通过 1 个 100G 线路口传输                  │
│                                                              │
│  路由器\#1 ──▶ 支路光口\#1 \(GE\) ──┐                             │
│  路由器\#2 ──▶ 支路光口\#2 \(GE\) ──┤                             │
│  路由器\#3 ──▶ 支路光口\#3 \(GE\) ──┤                             │
│  路由器\#4 ──▶ 支路光口\#4 \(GE\) ──┤                             │
│  路由器\#5 ──▶ 支路光口\#5 \(GE\) ──┤                             │
│  路由器\#6 ──▶ 支路光口\#6 \(GE\) ──┤                             │
│  路由器\#7 ──▶ 支路光口\#7 \(GE\) ──┤                             │
│  路由器\#8 ──▶ 支路光口\#8 \(GE\) ──┤                             │
│                                │                             │
│                    每个 GE → 1 个 ODU0                        │
│                    8 个 ODU0 → 复用进 1 个 ODU2                │
│                    ODU2 → 装入 ODU4 时隙                      │
│                                │                             │
│                                ▼                             │
│                    线路口: 1 个 100G 波长传输                   │
│                    \(内含 8 个 GE 业务\)                         │
│                                                              │
├──────────────────────────────────────────────────────────────┤
│                                                              │
│  方案C: 混合业务 → 1 个线路口                                  │
│  ─────────────────────────────                               │
│                                                              │
│  支路盘接入:                                                   │
│  ├── 支路口\#1: 2M × 16 \(电力专线\)                              │
│  ├── 支路口\#2: 2M × 16 \(银行专线\)                              │
│  ├── 支路口\#3: GE × 4  \(企业上网\)                              │
│  └── 支路口\#4: 10GE × 1 \(数据中心互联\)                         │
│                                                              │
│  映射:                                                         │
│  ├── 32 个 2M → 32 个 ODU0                                    │
│  ├── 4 个 GE → 4 个 ODU0                                      │
│  └── 1 个 10GE → 1 个 ODU2                                    │
│                                                              │
│  复用:                                                         │
│  ├── 36 个 ODU0 → 复用为 5 个 ODU2 \(36/8\=4\.5, 向上取整\=5\)      │
│  ├── 5 + 1 \= 6 个 ODU2                                        │
│  └── 6 个 ODU2 → 装入 ODU4 时隙\#1\~\#6                          │
│                                                              │
│  线路口: 1 个 100G 波长，内含 32 个 2M + 4 个 GE + 1 个 10GE    │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## 七、SDH 时代一个支路口接多业务

```text
SDH 时代: 1 个 STM-1 支路口承载多个 2M

  ┌──────────────────────────────────────────────────────────────┐
  │                                                              │
  │  1 个 STM-1 \(155M\) 支路口:                                    │
  │                                                              │
  │  ┌──────────────────────────────────────────────────────┐   │
  │  │  VC-4 \(155M 容器\)                                     │   │
  │  │  ┌────┬────┬────┬────┬────┬────┬────┬────┐          │   │
  │  │  │VC-3│VC-3│VC-3│VC-3│VC-3│VC-3│VC-3│    │          │   │
  │  │  │    │    │    │    │    │    │    │    │          │   │
  │  │  └──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴──┬─┴────┘          │   │
  │  │     │    │    │    │    │    │    │                   │   │
  │  │     ▼    ▼    ▼    ▼    ▼    ▼    ▼                   │   │
  │  │  每个 VC-3 可装:                                        │   │
  │  │  ├── 3 × TUG-3                                         │   │
  │  │  ├── 每个 TUG-3 \= 7 × TUG-2                            │   │
  │  │  ├── 每个 TUG-2 \= 3 × VC-12                            │   │
  │  │  └── 每个 VC-12 \= 1 个 2M                              │   │
  │  │                                                        │   │
  │  │  总计: 1 个 STM-1 \= 63 个 2M                            │   │
  │  └──────────────────────────────────────────────────────┘   │
  │                                                              │
  │  1 个支路口 \(STM-1\) \= 63 个 2M 业务通道                       │
  │  每个 2M 可以独立分配给不同客户                                 │
  └──────────────────────────────────────────────────────────────┘
```

## 八、总结

> **一个支路口接多个业务的核心方法：把高速口的带宽&quot;切&quot;成多个逻辑通道，每个通道承载不同的业务。**

|方式|技术|适用场景|示例|
| ------| ---------------| -------------| --------------------------|
|**物理分路**|分线器/分光器|简单场景|1×10GE → 10×GE|
|**逻辑分路**|VLAN/优先级|PTN/IP 网络|1×GE 承载语音+视频+上网|
|**OTN 复用**|ODUk 时隙划分|OTN 传输网|1×ODU4 \= 8×ODU2|
|**SDH 复用**|VC-4 → VC-12|SDH 传输网|1×STM-1 \= 63×2M|

**实际中最常见的方式**：

```text
不是"1个支路口接多个业务"
而是"多个支路口各接1个业务，然后复用到线路口"

  支路口\#1 \(2M\)  ──┐
  支路口\#2 \(2M\)  ──┤
  支路口\#3 \(GE\)  ──┼──▶ 交叉盘 ──▶ 线路口 \(100G\)
  支路口\#4 \(10GE\)──┤
  支路口\#5 \(10GE\)──┘

  每个支路口接 1 个业务
  多个支路口的业务在交叉盘复用到线路口
  这才是 OTN 设备的标准工作方式
```
