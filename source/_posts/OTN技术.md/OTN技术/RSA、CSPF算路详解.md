# RSA、CSPF算路详解

## 一、RSA 是什么

**RSA（Routing and Spectrum Assignment，路由与频谱分配）**  是 SDN 控制器为光网络业务连接**计算最优传输路径并分配频谱资源**的核心算法。

```text
RSA = Routing（路由）+ Spectrum Assignment（频谱分配）

  Routing：从源到目的，走哪条路径？经过哪些节点？
  Spectrum Assignment：在路径上分配哪个频率/波长？

  本质：一个 NP-hard 组合优化问题
  → 没有"完美"解法，只有"足够好"的近似解
```

## 三、RSA 的两大子问题

### 3.1 Routing（路由）

```text
目标：找到从源到目的的最优路径

"最优"的定义：
  · 最短距离 → 最小化传输损伤
  · 最少跳数 → 最小化设备故障风险
  · 最大 OSNR 余量 → 最大化可靠性
  · 最少拥塞 → 负载均衡

常用路由算法：
┌──────────────────────────────────────────────────┐
│ 1. 最短路径（Dijkstra / SPF）                     │
│    · 以距离/跳数为权重                             │
│    · 简单快速                                      │
│    · 不考虑频谱资源和 OSNR                        │
│                                                  │
│ 2. 约束最短路径（CSPF）                           │
│    · 在最短路径基础上加约束                         │
│    · 约束：OSNR ≥ 门限、距离 ≤ 上限               │
│    · 不满足约束则排除该链路再算                     │
│    · 工程中最常用                                  │
│                                                  │
│ 3. K 最短路径（KSP）                              │
│    · 找出 K 条候选路径（如 K=3）                   │
│    · 对每条路径再做频谱分配                         │
│    · 选综合最优的一条                               │
│    · 平衡质量和速度                                │
│                                                  │
│ 4. 负载均衡路由                                   │
│    · 考虑链路利用率                                 │
│    · 避开拥塞链路                                   │
│    · 适合大规模网络                                 │
└──────────────────────────────────────────────────┘
```

### 3.2 Spectrum Assignment（频谱分配）

```text
目标：在选定路径上分配可用的频谱资源

约束条件：
  · 频谱连续性：端到端必须使用同一组频率槽
  · 频谱非冲突：同一段光纤中不能有两个连接用同一频率槽
  · 频谱对齐（可选）：频率槽必须对齐到固定栅格

常用频谱分配策略：
┌──────────────────────────────────────────────────┐
│ 1. First Fit（首次适配）                          │
│    · 从低频到高频扫描，找第一个空闲的频谱块         │
│    · 速度最快                                      │
│    · 可能导致频谱碎片                               │
│                                                  │
│  频谱状态：[占用][空闲][空闲][空闲][占用][空闲]
│  First Fit：分配第2~4号槽（第一个连续空闲块）
│
│ 2. Last Fit（末次适配）                           │
│    · 从高频到低频扫描，找最后一个空闲的频谱块        │
│    · 有利于低频段集中使用                           │
│    · 可配合 First Fit 减少碎片                      │
│                                                  │
│ 3. Max Spectrum（最大频谱优先）                    │
│    · 选最大的连续空闲频谱块                         │
│    · 为未来扩容留空间                               │
│    · 适合需要灵活调整的场景                         │
│                                                  │
│ 4. Min Spectrum（最小频谱优先）                    │
│    · 选最小够用的连续空闲频谱块                     │
│    · 节省频谱资源                                   │
│    · 适合频谱紧张的场景                             │
│                                                  │
│ 5. Exact Fit（精确适配）                          │
│    · 选大小最接近需求的连续空闲频谱块               │
│    · 减少浪费                                      │
│    · 计算复杂度较高                                 │
└──────────────────────────────────────────────────┘
```

## 四、RSA 完整算法流程

```text
业务请求：A站 → D站，400G

Step 1：路由计算
┌──────────────────────────────────────────────────┐
│ PCE 模块：                                       │
│                                                  │
│ 网络拓扑：                                        │
│   A ──80km── B ──100km── D                      │
│   │                    │                         │
│   60km               120km                       │
│   │                    │                         │
│   C ──70km ────────── E                         │
│                                                  │
│ 候选路径（K=3）：                                 │
│   路径1：A→B→D（180km）                          │
│   路径2：A→C→E→D（250km）                        │
│   路径3：A→B→E→D（320km）                        │
│                                                  │
│ OSNR 可达性检查（400G DP-16QAM，需 OSNR≥22dB）： │
│   路径1（180km）：预估 OSNR=24dB ✓               │
│   路径2（250km）：预估 OSNR=20dB ✗ 不满足        │
│   路径3（320km）：预估 OSNR=16dB ✗ 不满足        │
│                                                  │
│ 路由结果：路径1（A→B→D）                          │
└──────────────────────────────────────────────────┘

Step 2：频谱分配
┌──────────────────────────────────────────────────┐
│ 400G 需要 4 个连续频率槽（每个 12.5GHz）          │
│                                                  │
│ 路径1 各段频谱状态：                               │
│   A-B 段：[λ1占][λ2占][λ3空][λ4空][λ5空][λ6空][λ7占]│
│   B-D 段：[λ1占][λ2空][λ3空][λ4占][λ5空][λ6空][λ7空]│
│                                                  │
│ 端到端共同空闲（频谱连续性约束）：                  │
│   λ3：A-B空 ∩ B-D空 = ✓ 连续4槽？               │
│     A-B：λ3,λ4,λ5,λ6 连续空闲 ✓                  │
│     B-D：λ3空闲，λ4占 ✗ → λ3开始只有1个连续       │
│                                                  │
│   λ5：A-B空 ∩ B-D空 = ✓ 连续4槽？               │
│     A-B：λ5,λ6 连续空闲（只有2个）✗               │
│                                                  │
│   重新检查：                                      │
│   A-B 连续空闲块：{λ3,λ4,λ5,λ6}（4个）           │
│   B-D 连续空闲块：{λ2,λ3}（2个）、{λ5,λ6,λ7}（3个）│
│                                                  │
│   端到端交集：                                    │
│   {λ3} 只有1个 → 不够4个 ✗                       │
│                                                  │
│   → 路径1 频谱不足！                              │
│   → 需要重新选路或换调制格式                       │
│                                                  │
│ 回退方案：                                        │
│   改用 DP-QPSK（200G×2 超级通道）                 │
│   需要 OSNR≥15dB，每个子载波2个频率槽              │
│   路径2（250km）：OSNR=20dB ✓ 可达               │
│   重新做频谱分配...                               │
│                                                  │
│ 最终结果：                                        │
│   路径：A→B→D                                    │
│   频谱：λ5,λ6（2个连续槽，200G DP-QPSK ×2）      │
│   或：路径2 + 其他频谱组合                        │
└──────────────────────────────────────────────────┘

Step 3：配置下发
┌──────────────────────────────────────────────────┐
│ 控制器通过 NETCONF 下发：                         │
│                                                  │
│ A站：创建 OCH，频谱 λ5+λ6，DP-QPSK              │
│ B站：WSS 穿通 λ5+λ6                             │
│ D站：接收 OCH，频谱 λ5+λ6                       │
│                                                  │
│ 更新 TED：标记 λ5,λ6 在 A-B 和 B-D 段已占用      │
└──────────────────────────────────────────────────┘
```

### 物理层验证

#### 5.1 OSNR 可达性验证

```text
选定路径：A → C → D
选定频谱：Slot 2~3

OSNR 计算：
┌──────────────────────────────────────────┐
│ 各段 OSNR 计算：                          │
│                                          │
│ A-C 段（80km）：                          │
│   衰耗 = 80 × 0.25 = 20 dB              │
│   EDFA 噪声 = 5 dB（NF=5dB）            │
│   OSNR_A-C = 58 - 20 + 17 - NF = 30 dB  │
│                                          │
│ C-D 段（90km）：                          │
│   衰耗 = 90 × 0.25 = 22.5 dB            │
│   EDFA 噪声 = 5 dB                       │
│   OSNR_C-D = 58 - 22.5 + 17 - 5 = 28 dB │
│                                          │
│ 端到端 OSNR（级联）：                     │
│   1/OSNR_total = 1/OSNR_A-C + 1/OSNR_C-D│
│   OSNR_total ≈ 25 dB                     │
│                                          │
│ 验证：                                    │
│   200G DP-8QAM 要求 OSNR ≥ 18 dB        │
│   25 dB ≥ 18 dB ✓ 可达！                 │
│   余量 = 25 - 18 = 7 dB                  │
└──────────────────────────────────────────┘
```

## 五、RSA 算法分类

|算法类型|方法|优点|缺点|适用场景|
| ----------| --------------------------| ----------------| ----------------------------| ----------------------|
|**ILP（整数线性规划）**|数学建模求全局最优|结果最优|复杂度高，大规模网络算不动|小型网络/离线规划|
|**启发式算法**|贪心策略（KSP+FirstFit）|速度快，可扩展|不保证全局最优|在线实时算路（主流）|
|**元启发式算法**|遗传算法/模拟退火|跳出局部最优|参数调优复杂|中大规模网络优化|
|**机器学习**|深度强化学习|自适应、智能|训练成本高|前沿研究|

### 启发式算法（工程主流）

```text
启发式 RSA 算法流程：

  输入：业务请求 + TED
  
  Step 1：用 KSP 找 K 条候选路径
  Step 2：对每条路径，用 FirstFit 分配频谱
  Step 3：检查每条路径+频谱组合的 OSNR 可达性
  Step 4：从可行解中选"最优"（如 OSNR 余量最大）
  Step 5：无可行解 → 尝试调整调制格式 → 重新计算
  Step 6：仍无解 → 返回"阻塞"（资源不足）
  
  输出：最优路径+频谱方案 或 "阻塞"
  
  时间复杂度：O(K × N)
  · K = 候选路径数（通常 3~5）
  · N = 频谱扫描次数
  · 通常 < 100ms 可完成
```

## 六、RSA 的核心约束总结

|约束|含义|影响|
| ------| -------------------------------------| ----------------------------|
|**波长连续性**|端到端必须同一波长（无 OEO 再生时）|路径选择受限，可能需换波长|
|**频谱连续性**|FlexGrid 下必须连续频率槽|频谱碎片导致分配失败|
|**频谱非冲突**|同段光纤同频率不能复用|必须找空闲频谱|
|**OSNR 可达**|端到端 OSNR ≥ 调制格式要求|限制最大传输距离|
|**调制格式约束**|不同调制格式有不同距离限制|可能需要降阶调制|
|**保护约束**|1+1 保护需找两条分离路径|路由分离度要求|

## 八、一句话总结

> **RSA 算路**是 SDN 控制器的"大脑"——**Routing** 解决"走哪条路"（CSPF/KSP 找最优路径，满足 OSNR/距离约束），**Spectrum Assignment** 解决"用哪个波长"（FirstFit/MaxFit 分配频谱，满足连续性和非冲突约束）。两者联合求解是 **NP-hard 问题**，工程上采用**启发式算法**（K 最短路径 + 首次适配）在 100ms 内给出"足够好"的方案。核心约束包括**波长连续性、频谱连续性、频谱非冲突、OSNR 可达**——任何一个约束不满足，都可能导致业务"阻塞"（无法开通）。RSA 被新业务开通、故障恢复、多路径预置、网络优化等场景反复调用，是光网络自动化的核心引擎。
