# 传输网DCI SDN介绍

---

### 一、什么是SDN控制器

SDN控制器是软件定义网络（SDN）的 **&quot;大脑&quot;** ，将传统网络设备中的控制平面功能**集中到一台独立的软件平台上**，实现网络的统一管控、自动化编排和智能优化。

```text
传统网络：每台设备都有"大脑"，各自为政
  ┌──────┐    ┌──────┐    ┌──────┐
  │设备A  │    │设备B  │    │设备C  │
  │🧠转发 │    │🧠转发 │    │🧠转发 │
  └──────┘    └──────┘    └──────┘

SDN网络：一个"大脑"管所有设备
              ┌──────────┐
              │ SDN控制器 │
              │  🧠全局大脑│
              └─────┬────┘
                    │
          ┌─────────┼─────────┐
          ▼         ▼         ▼
       ┌──────┐ ┌──────┐ ┌──────┐
       │设备A  │ │设备B  │ │设备C  │
       │ 转发  │ │ 转发  │ │ 转发  │
       └──────┘ └──────┘ └──────┘
```

### 三、六大核心功能模块

#### 模块1：拓扑管理（TED - Traffic Engineering Database）

```text
功能：构建并维护全网实时拓扑

数据来源：
  ├── 设备通过PCEP上报邻居和链路信息
  ├── NETCONF获取设备配置和端口状态
  └── Telemetry采集实时性能数据

TED中存储的信息：
  ├── 节点信息：设备ID、类型、角色、状态
  ├── 链路信息：源/目的、带宽、时延、OSNR
  ├── 资源信息：可用波长、空闲时隙、端口占用
  └── 约束信息：保护类型、管理域归属、策略限制

输出：为路径计算提供全局网络视图
```

#### 模块2：路径计算引擎（PCE）

```text
功能：为新业务计算最优传输路径

输入：
  ├── 源/目的节点
  ├── 带宽需求
  ├── 约束条件（排除链路、必经节点）
  └── TED中的全网状态

算法：
  ├── CSPF（约束最短路径优先）—— 传统WDM
  ├── RSA（路由+频谱分配）—— 弹性光网络
  └── K-Shortest Path + QoT验证

输出：
  ├── 最优路径（节点序列）
  ├── 资源分配方案（波长/时隙）
  ├── 调制格式（QPSK/16QAM/64QAM）
  └── 保护路径（1+1/1:1）
```

#### 模块3：连接管理（LSP Manager）

```text
功能：管理端到端连接的完整生命周期

生命周期：
  ┌──────┐   ┌──────┐   ┌──────┐   ┌──────┐
  │ 创建  │──→│ 激活  │──→│ 监控  │──→│ 删除  │
  └──────┘   └──────┘   └──────┘   └──────┘
                │                      ↑
                └─── 修改/优化 ────────┘

操作内容：
  ├── 生成交叉配置（源/目的端口、时隙、波长）
  ├── 通过NETCONF逐台设备下发
  ├── 验证每台设备的交叉状态
  ├── 维护LSP数据库（全局连接表）
  └── 按需修改/优化已有连接
```

#### 模块4：保护与恢复

```text
功能：故障时自动保障业务不中断

保护方式：
  ├── 1+1保护：工作+保护路径同时建立
  │   故障 → 直接切换（\<50ms）
  │
  ├── 1:1保护：保护路径预留但不传业务
  │   故障 → 切换到保护路径（\<50ms）
  │
  ├── 恢复（Restoration）：故障后重新算路
  │   故障 → 控制器重算路径 → 下发新交叉（秒级）
  │
  └── 预置恢复（Pre-planned）：提前算好恢复路径
      故障 → 直接激活预置路径（比恢复更快）

故障检测：
  ├── 设备通过PCEP/Telemetry上报LOS/LOF/SD
  ├── BFD检测链路连通性
  └── 控制器分析性能劣化趋势（AI预测）
```

#### 模块5：资源管理

```text
功能：统一管理全网波长、时隙、端口资源

管理内容：
  ├── 波长资源：每个光纤段的λ1\~λ80占用情况
  ├── 时隙资源：每个波长内的ODUk时隙分配
  ├── 端口资源：支路口/线路口的带宽利用率
  └── 频谱碎片：记录和优化频谱碎片化

核心能力：
  ├── 资源预占：业务开通前预占资源，避免冲突
  ├── 资源释放：业务删除后释放资源，归还资源池
  ├── 碎片整理：定期优化频谱分配，减少碎片
  └── 容量预警：资源使用率\>80%时告警
```

#### 模块6：业务编排（Service Orchestrator）

```text
功能：端到端业务自动开通（零接触）

传统方式（人工）：
  ① 客户经理接单 → ② 规划人员设计方案 → ③ 网管登录设备A配置
  → ④ 网管登录设备B配置 → ⑤ 网管登录设备C配置 → ⑥ 逐段测试
  耗时：天\~周级别

SDN方式（自动）：
  ① OSS下发业务工单（REST API）
  → ② 控制器自动算路+分配资源
  → ③ 控制器批量下发交叉配置
  → ④ 控制器自动验证
  耗时：分钟\~秒级别
```

### 四、核心接口体系

```text
┌──────────────────────────────────────────────────┐
│                  SDN控制器                        │
│                                                  │
│  北向上层接口（面向OSS/应用）                      │
│  ┌────────────────────────────────────────────┐  │
│  │  REST API（HTTP/HTTPS + JSON）              │  │
│  │  ·业务开通接口  ·拓扑查询接口               │  │
│  │  ·告警推送接口  ·性能查询接口               │  │
│  │  ·资源查询接口  ·路径计算接口               │  │
│  └────────────────────────────────────────────┘  │
│                                                  │
│  南向设备接口（面向传输设备）                      │
│  ┌────────────────────────────────────────────┐  │
│  │  NETCONF/YANG（TCP/830）                    │  │
│  │  ·配置下发  ·状态查询  ·事件订阅            │  │
│  ├────────────────────────────────────────────┤  │
│  │  PCEP（TCP/830）                            │  │
│  │  ·路径请求/响应  ·LSP状态上报  ·建路指令    │  │
│  ├────────────────────────────────────────────┤  │
│  │  Telemetry（gRPC/UDP）                      │  │
│  │  ·实时性能数据推送（光功率/OSNR/误码）       │  │
│  ├────────────────────────────────────────────┤  │
│  │  SNMP（UDP/161）                            │  │
│  │  ·告警采集  ·性能轮询（兼容存量设备）        │  │
│  └────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────┘
```

|接口|方向|协议|核心用途|
| ------| ----------------| -------------| -------------------------|
|**REST API**|北向（→OSS）|HTTP+JSON|业务编排、数据查询|
|**NETCONF**|南向（→设备）|TCP/SSH+XML|配置下发、状态查询|
|**PCEP**|南向（↔设备）|TCP+二进制|路径交互、状态上报|
|**Telemetry**|南向（←设备）|gRPC/UDP|实时性能采集|
|**SNMP**|南向（←设备）|UDP|告警/性能（兼容老设备）|

### 五、核心数据模型

```text
控制器内部核心数据结构：

1\. TED（流量工程数据库）
├── Node\{ID, Type, Role, Status, Location\}
├── Link\{SrcNode, DstNode, Bandwidth, Delay, OSNR, Status\}
├── Wavelength\{LinkID, λ\_Index, Status, OccupiedBy\}
└── Timeslot\{WavelengthID, Slot\_Index, Status, OccupiedBy\}

2\. LSP数据库（连接表）
├── LSP\{ID, SrcPort, DstPort, Path\[\], Wavelength, Timeslots\[\]\}
├── Protection\{LSP\_ID, Type, WorkingPath, ProtectPath\}
└── Service\{LSP\_ID, CustomerID, Bandwidth, SLA\_Level\}

3\. 策略数据库
├── RoutingPolicy\{SrcRange, DstRange, Constraint, Priority\}
├── QoSPolicy\{ServiceType, MinBandwidth, MaxDelay, MaxBER\}
└── ResourcePolicy\{MaxUtilization, ReservedCapacity, FragmentLimit\}
```

### 八、核心工作流程总结

```text
完整业务流程：

① 业务请求
   OSS通过REST API提交：源/目的/带宽/SLA
        │
        ▼
② 拓扑查询
   控制器从TED获取当前全网状态
        │
        ▼
③ 路径计算
   PCE运行RSA/CSPF算法
   输出：最优路径 + 波长/时隙 + 调制格式
        │
        ▼
④ 资源预占
   在TED中标记资源为"已预占"，防止冲突
        │
        ▼
⑤ 交叉下发
   通过NETCONF逐台设备下发交叉配置
   顺序：目的→中间→源（避免数据丢失）
        │
        ▼
⑥ 验证确认
   NETCONF查询每台设备交叉状态
   全部Active → 业务开通成功
        │
        ▼
⑦ 持续监控
   Telemetry持续采集性能数据
   异常时触发保护恢复
        │
        ▼
⑧ 业务删除
   NETCONF逐台删除交叉 → 释放资源回资源池
```

---

**一句话总结**：SDN控制器是传输网络的**集中式大脑**，核心做三件事——**看全网**（拓扑管理TED）、**算路径**（PCE/RSA算法）、**下配置**（NETCONF逐台下发交叉）。通过北向上层REST API对接OSS，通过南向NETCONF/PCEP/Telemetry管控全网设备，实现业务自动开通、智能保护和资源优化。掌握SDN控制器开发，核心就是掌握**路径计算算法 + NETCONF/YANG协议 + 资源管理逻辑**这三大技术支柱。
