# 传输控制平面

### 未来趋势

|趋势|说明|对开发者的意义|
| ------| --------------------------------| ---------------------------|
|**集中式SDN控制**|从分布式GMPLS向SDN集中控制演进|需掌握SDN架构+控制器开发|
|**PCE增强**|Hierarchical PCE、跨域PCE|需掌握分布式计算+多域协调|

### 三、控制平面的发展演进

#### 分布式控制平面（ASON/GMPLS）

```text
OTN-A ←─GMPLS─→ OTN-B ←─GMPLS─→ OTN-C
  │                │                │
  每台设备自带      每台设备自带      每台设备自带
  控制平面模块      控制平面模块      控制平面模块
  独立算路          独立算路          独立算路
```

* 每台设备内置控制平面（GMPLS协议栈）
* 设备之间通过协议**自动协商**建立连接
* 支持自动保护恢复（\<50ms）
* **代表技术**：ASON（自动交换光网络）

#### 集中式控制平面（SDN）—— 当前主流

```text
              ┌──────────────────────┐
              │    SDN控制器          │
              │   （集中大脑）        │
              │   全局拓扑+统一算路   │
              └──────────┬───────────┘
                         │ PCEP/NETCONF
              ┌──────────┼───────────┐
              ▼          ▼           ▼
           OTN-A      OTN-B       OTN-C
          （哑设备，只执行转发）
```

* 控制器拥有**全局网络视图**
* 集中计算最优路径，统一调度资源
* 设备简化为"哑转发"，降低设备复杂度
* **代表产品**：华为iMaster NCE、中兴ZENIC ONE

#### 分布式+集中式混合（未来趋势）

```text
         ┌──────────────────────────┐
         │      SDN控制器            │
         │   （全局编排+跨域协调）    │
         └────────────┬─────────────┘
                      │ 宏观策略
         ┌────────────┼─────────────┐
         ▼            ▼             ▼
      ┌──────┐    ┌──────┐     ┌──────┐
      │域控制器│    │域控制器│     │域控制器│
      │\(分布式\)│    │\(分布式\)│     │\(分布式\)│
      └──┬───┘    └──┬───┘     └──┬───┘
         │           │            │
      OTN域A      OTN域B       OTN域C
```

* 集中控制器负责**跨域编排和全局策略**
* 域内由分布式控制平面**快速自主决策**
* 兼顾全局最优与局部快速响应

### 四、控制平面核心协议详解

#### 1. GMPLS（通用多协议标签交换）

**定位**：ASON分布式控制平面的基础协议族

```text
GMPLS协议族：
┌─────────────────────────────────────────┐
│  路由协议：OSPF-TE / IS-IS-TE           │  ← 拓扑发现
├─────────────────────────────────────────┤
│  信令协议：RSVP-TE / CR-LDP             │  ← 连接建立
├─────────────────────────────────────────┤
│  链路管理：LMP（链路管理协议）            │  ← 邻居发现
├─────────────────────────────────────────┤
│  路径计算：CSPF（约束最短路径优先）       │  ← 路径选择
└─────────────────────────────────────────┘
```

**RSVP-TE信令流程（建立LSP）：**

```text
OTN-A（源）              OTN-B（中间）           OTN-C（目的）
   │                       │                      │
   │─── Path消息 ─────────→│─── Path消息 ────────→│
   │   \(携带约束条件\)       │   \(转发\)              │
   │                       │                      │
   │                       │←─── Resv消息 ────────│
   │←─── Resv消息 ─────────│   \(预留资源\)          │
   │   \(确认建立\)          │                      │
   │                       │                      │
   │   ═══ LSP建立完成，数据开始转发 ═══           │
```

#### 2. PCEP（路径计算单元通信协议）

**定位**：SDN集中控制平面中，设备与控制器之间的通信协议

```text
PCEP核心消息：

设备PCC → 控制器PCE：
  ├→ PCRpt（上报LSP状态）
  ├→ PCReq（请求计算路径）
  └→ PCUpd（更新LSP属性）

控制器 → 设备：
  ├→ PCRep（返回计算结果）
  ├→ PCInitiate（下发LSP建立指令）
  └→ PCUpd（更新LSP参数）
```

**PCEP建立业务完整流程：**

```text
OTN-A                    SDN控制器                  OTN-C
  │                         │                        │
  │── PCRpt\(拓扑\) ─────────→│                        │
  │                         │  ← 控制器构建全局拓扑   │
  │                         │                        │
  │    业务请求（UNI口→UNI口）                        │
  │────────────────────────→│                        │
  │                         │                        │
  │                         │  ← 计算最优路径         │
  │                         │    A→B→C，波长λ1       │
  │                         │                        │
  │←── PCInitiate ──────────│──── PCInitiate ───────→│
  │   \(配置交叉:时隙1→λ1\)   │   \(配置交叉:λ1→时隙1\)  │
  │                         │                        │
  │── PCRpt\(LSP建立成功\) ──→│←── PCRpt\(LSP建立成功\) ─│
  │                         │                        │
  │   ═══ 端到端LSP建立完成 ═══                      │
```

#### 3. 协议对比

|维度|GMPLS（分布式）|PCEP（集中式SDN）|
| ------| ----------------------| ------------------------|
|**算路位置**|每台设备自己算|控制器集中算|
|**拓扑视图**|每台设备只知道邻居|控制器知道全网|
|**路径质量**|局部最优|全局最优|
|**响应速度**|快（本地算路）|稍慢（需与控制器交互）|
|**跨域能力**|差（需复杂协议扩展）|强（控制器统一协调）|
|**扩展性**|差（设备负担重）|好（设备简化）|
|**可靠性**|高（无单点故障）|依赖控制器可靠性|

### 五、控制平面核心功能

#### 功能1：自动发现（Auto-Discovery）

```text
控制平面自动发现的内容：
├→ 邻居设备：通过Hello协议发现直连邻居
├→ 链路状态：带宽、可用波长/时隙、保护类型
├→ 拓扑构建：自动构建全网拓扑图
└→ 资源同步：实时更新可用资源信息
```

#### 功能2：路径计算（Path Computation）

```text
CSPF算法输入：
├→ 源/目的节点
├→ 带宽需求（如ODU2 \= 10G）
├→ 约束条件（排除某段光纤、必须经过某节点）
├→ 保护等级（1+1/1:1/无保护）
└→ 优先级

CSPF算法输出：
├→ 最优路径（节点序列：A→B→D→C）
├→ 波长/时隙分配（λ1, 时隙1\~8）
└→ 保护路径（如有）（A→E→C）
```

#### 功能3：连接建立（Connection Setup）

```text
路径计算完成后：
├→ 控制器通过NETCONF向每台设备下发交叉连接配置
│   OTN-A: 支路口1 → 时隙1
│   OTN-B: 时隙1 → 时隙1（直通）
│   OTN-C: 时隙1 → 线路口1
├→ 或通过RSVP-TE信令逐跳建立
└→ 端到端LSP建立完成
```

#### 功能4：保护与恢复（Protection & Restoration）

```text
保护方式：
├→ 1+1保护：工作路径+保护路径同时建立
│   故障时直接切换到保护路径（\<50ms）
│
├→ 1:1保护：保护路径预留但不传业务
│   故障时切换到保护路径（\<50ms）
│
├→ 恢复（Restoration）：故障后重新计算路径
│   速度较慢（秒级），但资源利用率高
│
└→ 共享保护（Shared Protection）：多条LSP共享保护资源
    节省资源，但可能冲突
```

**保护倒换流程：**

```text
正常工作：
OTN-A ══工作路径══→ OTN-B ══→ OTN-C（数据正常传输）

光纤中断！
OTN-A ══工作路径══→ ✕（断） ══→ OTN-C

控制平面检测到故障（\<10ms）
  │
  ├→ 1+1保护：立即切换到保护路径（\<50ms）
  │   OTN-A ══保护路径══→ OTN-D ══→ OTN-C
  │
  └→ 恢复模式：重新计算路径
      控制器计算新路径 → 下发配置 → 新LSP建立
```

ASON是控制平面在传输网络中最成熟的应用：

```text
ASON参考架构：

┌──────────────────────────────────────────────┐
│              管理平面（OSS/NMS）              │
│         业务编排、策略管理、计费               │
└──────────────────┬───────────────────────────┘
                   │ CI（连接控制器接口）
┌──────────────────┴───────────────────────────┐
│              控制平面（ASON控制平面）           │
│                                              │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐   │
│  │ 路由协议  │  │ 信令协议  │  │ 路径计算  │   │
│  │OSPF-TE   │  │RSVP-TE   │  │ CSPF     │   │
│  └──────────┘  └──────────┘  └──────────┘   │
│                                              │
│  ┌──────────┐  ┌──────────┐                  │
│  │ 链路管理  │  │ 自动发现  │                  │
│  │ LMP      │  │ Auto-    │                  │
│  │          │  │ Discovery│                  │
│  └──────────┘  └──────────┘                  │

                   │ DC（数据通信网）
```

|连接类型|建立方式|速度|适用场景|
| ----------| -----------------------| -----------| --------------------|

|**SPC（软永久连接）**|管理平面+控制平面协同|秒级|半动态业务|
|**PC（永久连接）**|管理平面手动配置|分钟/小时|固定专线|

**一句话总结**：传输控制平面是光网络的"智能大脑"，从ASON分布式（GMPLS）演进到SDN集中式（PCEP），核心解决三个问题——**路怎么算（路径计算）、连接怎么建（信令交互）、断了怎么办（保护恢复）** 。掌握控制平面开发，需要同时具备通信协议功底（GMPLS/PCEP/RSVP-TE）和算法能力（CSPF/RSA），是传输领域技术壁垒最高的方向。

## RSA vs CSPF 对比

---

### 一、一句话区分

> **CSPF**  **=**  **选路（只解决&quot;走哪条路&quot;）**   
> **RSA**  **=**  **选路 + 选波长（解决&quot;走哪条路&quot; + &quot;用哪段频谱&quot;）**

RSA是CSPF在弹性光网络中的**升级版**。

---

### 二、基本定位

|维度|CSPF|RSA|
| ------| ---------------------------------| ---------------------------------|
|**全称**|Constrained Shortest Path First|Routing and Spectrum Assignment|
|**中文**|约束最短路径优先|路由与频谱分配|
|**应用时代**|传统WDM/固定栅格光网络|弹性光网络（EON/FlexGrid）|
|**解决的问题**|只选路径|选路径 + 选频谱|
|**频谱模型**|固定波长网格（50GHz/100GHz）|灵活频谱栅格（12.5GHz粒度）|
|**算法复杂度**|较低（多项式时间）|高（NP-hard）|
