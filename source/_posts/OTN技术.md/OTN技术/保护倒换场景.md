# 保护倒换场景

## 故障检测

### 一、核心问题

合波后，所有波长都在**同一根光纤**里传输，网管/控制器怎么知道是**哪一波**出了问题？单波故障如何被检测并触发重路由？

```text
合波后的光纤里：
λ1 λ2 λ3 λ4 \.\.\. λn  ← 全在一根光纤里
         ↑
      λ3 出问题了
         ↓
   如何单独检测 λ3？
   如何只让 λ3 触发重路由？
   λ1 λ2 λ4 不受影响？
```

---

### 二、单波故障检测机制

#### 2.1 每波独立携带开销——OCH 层开销

OTN 标准中，**每个波长（OCH）都有独立的开销字节**，即使合波后也能逐波监控：

```text
OTUk 帧结构（每个波长独立成帧）：
┌──────────┬──────────┬──────────────┬──────────┐
│ 帧对齐    │ OTUk开销  │ ODUk净荷     │ FEC      │
│ FAS      │ SM-BIP-8 │ 客户数据      │          │
│          │ TTI      │              │          │
│          │ GCC      │              │          │
└──────────┴──────────┴──────────────┴──────────┘

关键：每个波长都有自己的 OTUk 帧
→ λ1 有自己的帧和开销
→ λ2 有自己的帧和开销
→ 各波独立监控，互不干扰
```

#### 2.2 接收端线路盘逐波检测

```text
合波光信号到达接收端：
│
│ λ1+λ2+λ3+\.\.\.+λn（合波信号）
▼
┌──────────────────────────────────────────┐
│ 接收端线路盘                              │
│                                          │
│ 1\. 光前端：分波器（DEMUX）将各波长分开     │
│    λ1 → 接收器1                          │
│    λ2 → 接收器2                          │
│    λ3 → 接收器3  ← 检测到故障！           │
│    λ4 → 接收器4                          │
│                                          │
│ 2\. 每个接收器独立处理：                    │
│    - 光电转换                             │
│    - 帧对齐检测（FAS）                    │
│    - SM-BIP-8 误码检测                   │
│    - FEC 纠错前误码率（pre-FEC BER）      │
│    - 信号丢失检测（LOS）                  │
│                                          │
│ 3\. 逐波上报状态给主控盘                   │
│    λ1：正常                              │
│    λ2：正常                              │
│    λ3：pre-FEC BER 超标 ← 告警！         │
│    λ4：正常                              │
└──────────────────────────────────────────┘
```

#### 2.3 单波检测的关键指标

|检测指标|含义|触发条件|
| ----------| --------------------| ---------------------------|
|**LOS**|该波长完全无光信号|光功率低于阈值|
|**LOF**|该波长帧失步|帧对齐字节连续错误|
|**OTU-AIS**|上游通知本波长故障|收到告警指示信号|
|**SM-BIP-8 误码**|该波长段层误码超标|BIP-8 校验不通过|
|**pre-FEC BER**|该波长纠错前误码率|超过设定门限（如 10⁻³）|
|**OSNR 劣化**|该波长光信噪比不足|低于调制格式要求|

### 三、单波触发重路由的完整流程

```text

│ λ1 接收器：正常 ✓                    │

│                                      │
│ 排查各段 λ3 状态：                    │

│                                      │

              ▼
Step 5：仅对 λ3 下发配置

│                                      │

│   → λ3 发送切换到新路径 A→E          │
│   → 波长改为 λ7                      │
│   → λ1/λ2/λ4 发送不变！              │
│                                      │
│ E站：                                │
│   → 光交叉 WSS 配置 λ7 穿通          │

│   → 光交叉 WSS 配置 λ7 穿通          │
│                                      │
```

### 四、单波触发的技术基础

#### 4.1 为什么能单独检测每一波？

```text
合波 ≠ 混在一起分不清

实际上每个波长：
1. 频率不同（λ1=192.1THz，λ2=192.2THz...）→ 分波器可分开
2. 各自独立成帧（各有 OTUk 帧结构）→ 开销独立
3. 各有独立的 FEC 校验 → 误码率独立统计
4. 各有独立的光功率 → 可逐波监控

→ 合波传输 ≠ 信号混合
→ 接收端分波后，每波独立处理，互不影响
```

#### 4.2 中间站（穿通站）如何监控单波？

```text
中间站 C（光交叉穿通）：

合波光信号进入 C 站
    │
    ▼
┌──────────────────────────────────────┐
│ C站 ROADM/WSS 模块：                 │
│                                      │
│ 方式1：MON 口采样监控                 │
│ → 从合波信号中分出一小部分（~1%）     │
│ → 送到 OPM（光功率监控板）            │
│ → OPM 分析各波长光功率和 OSNR        │
│ → 逐波上报：λ1正常、λ2正常、λ3异常   │
│                                      │
│ 方式2：OSC 开销通道                   │
│ → 每波的 OTUk 开销通过 OSC 回传控制器 │
│ → 控制器可逐波查看 SM-BIP-8 状态     │
│                                      │
│ 穿通动作：                            │
│ → λ1/λ2/λ4 正常穿通（WSS 直通）      │
│ → λ3 异常 → 上报控制器，等待指令      │
└──────────────────────────────────────┘
```

#### 4.3 逐波监控的硬件支撑

|硬件|功能|位置|
| ------| ---------------------------------| -------------------------|
|**OPM（光功率监控板）**|分析合波信号中各波长功率和 OSNR|每个站点（通过 MON 口）|
|**线路盘接收器**|逐波光电转换、帧检测、FEC 统计|终端站|
|**WSS（波长选择开关）**|逐波调度、穿通或下路|ROADM 站点|
|**OSC 板**|传递光层开销和监控信息|每个站点|

### 五、单波触发 vs 整纤触发的区别

```text
场景：B→C 段光纤中 λ3 劣化（其他波长正常）

单波触发（OCH 级重路由）：
┌──────────────────────────────────┐
│ λ1：不动 ✓                      │
│ λ2：不动 ✓                      │
│ λ3：触发重路由 → 切到新路径 ✓    │
│ λ4：不动 ✓                      │
│                                  │
│ 影响范围：仅 λ3 对应业务短暂中断  │
│ 资源消耗：仅新路径占用一个波长    │
└──────────────────────────────────┘

整纤触发（OMSP 级保护）：
┌──────────────────────────────────┐
│ λ1：一起切到保护光纤              │
│ λ2：一起切到保护光纤              │
│ λ3：一起切到保护光纤              │
│ λ4：一起切到保护光纤              │
│                                  │
│ 影响范围：所有波长业务都倒换      │
│ 资源消耗：整根保护光纤被占用      │
└──────────────────────────────────┘
```

|对比项|单波触发（OCH 重路由）|整纤触发（OMSP）|
| ----------| ------------------------| ------------------|
|检测粒度|逐波独立检测|整纤检测|
|触发范围|仅故障波长|所有波长|
|业务影响|最小（仅故障波）|大（全部倒换）|
|资源消耗|低（仅占一个波长）|高（占整根光纤）|
|倒换速度|秒级|\< 50ms|
|适用场景|单波故障/劣化|光纤断裂|

### 六、一句话总结

> **合波后单波触发重路由的关键**：每个波长独立成帧（各有 OTUk 开销和 FEC），接收端分波后逐波独立检测——谁出问题只报谁；SDN 控制器收到单波告警后，**只重路由故障波长**，其他波长纹丝不动。实现基础是：波长频率不同可分离、开销独立可监控、FEC 独立可统计、WSS 可逐波调度——**合波传输但分波管控**，这就是 WDM 的精髓。

## 导致单波劣化的六大原因

### 原因 1：光放大器增益不平坦（最常见）

```text
EDFA 放大器的增益特性：
增益(dB)
  ↑
  │        ╭──────╮
  │       ╱        ╲
  │      ╱          ╲
  │     ╱            ╲
  │    ╱              ╲
  │───╱────────────────╲───
  └──────────────────────→ 波长(nm)
     1530  1550  1565

  中心波长（~1550nm）增益高
  边缘波长（1530/1565nm）增益低

  结果：
  λ1(1550nm) → 放大充分 → 功率正常 ✓
  λ2(1535nm) → 放大不足 → 功率偏低 → OSNR劣化 ✗
  λ3(1560nm) → 放大不足 → 功率偏低 → OSNR劣化 ✗
```

> **多个光放段级联后，不平坦效应会累积**——经过 5 个光放段后，边缘波长和中心波长的功率差可达 **5~10dB**。

### 原因 2：光纤色散对不同波长影响不同

```text
色散特性：
  零色散波长（λ0）附近：色散小 → 信号质量好
  远离零色散波长：色散大 → 信号劣化

  例：G.652 光纤零色散波长 = 1310nm

  λ1(1550nm) → 距1310nm远 → 色散大 → 但已用DCF补偿 ✓
  λ2(1530nm) → 距1310nm更远 → 残余色散更大 → 可能超标 ✗

  色散补偿通常针对中心波长优化
  → 边缘波长补偿不完美 → 残余色散更大 → 误码率更高
```

### 原因 3：光纤非线性效应（选择性攻击特定波长）

```text
四波混频（FWM）：
  当多个波长的间隔满足特定关系时：
  λ1 + λ2 → 产生新频率 λ3' = 2λ1 - λ2
  
  新频率如果恰好落在某个信号波长上：
  → 该波长受到严重干扰
  → 其他波长不受影响

  例：
  λ1(192.1) + λ2(192.3) → 产生 191.9
  如果 λ3 正好在 191.9 → λ3 被干扰 ✗
  λ4(192.5) 不受影响 ✓

受激拉曼散射（SRS）：
  短波长把能量"转移"给长波长
  → 短波长功率下降 → OSNR劣化
  → 长波长功率上升 → 可能过载
  → 各波长受影响程度不同
```

### 原因 4：发送端激光器个体差异

```text
每个波长由独立的激光器产生：

  激光器1（λ1）→ 新品，性能优良 → 信号质量好 ✓
  激光器2（λ2）→ 新品，性能优良 → 信号质量好 ✓
  激光器3（λ3）→ 老化/温漂 → 输出光功率偏低 → 信号差 ✗
  激光器4（λ4）→ 新品，性能优良 → 信号质量好 ✓

  → 每个激光器是独立器件，个体差异必然存在
  → 老化程度、温度漂移、偏置电流偏差各不相同
```

### 原因 5：ROADM/WSS 波长相关损耗

```text
ROADM 站点中 WSS（波长选择开关）的特性：

  WSS 对每个波长的衰减不完全一致：
  
  λ1 → WSS 衰耗 3dB → 正常 ✓
  λ2 → WSS 衰耗 3dB → 正常 ✓
  λ3 → WSS 衰耗 5dB → 偏高（器件偏差）→ 功率低 ✗
  λ4 → WSS 衰耗 3dB → 正常 ✓

  经过多个 ROADM 站点后：
  λ3 累积额外损耗 → 越来越弱 → 最终 OSNR 不达标
```

### 原因 6：滤波器级联效应（穿通站累积）

```text
每个 ROADM 站都有滤波器（WSS/TF）：

  第1站：滤波器对 λ3 有 0.5dB 额外损耗
  第2站：滤波器对 λ3 又有 0.5dB 额外损耗
  第3站：滤波器对 λ3 又有 0.5dB 额外损耗
  ...
  第10站：λ3 累积了 5dB 额外损耗 → 严重劣化 ✗

  而 λ1/λ2/λ4 每次额外损耗只有 0.1dB
  → 10站后累积 1dB → 基本正常 ✓

  这就是"滤波器级联效应"
  → 不同波长经过多个站点后差异越来越大
```

### 三、综合示意

```text
业务开通时各波长状态一样（都是新分配的）：
  λ1: ████████ 100%  ✓
  λ2: ████████ 100%  ✓
  λ3: ████████ 100%  ✓
  λ4: ████████ 100%  ✓

经过 5 个光放段 + 3 个 ROADM 站后：
  λ1: ███████░ 95%  ✓（正常）
  λ2: ███████░ 92%  ✓（正常）
  λ3: ████░░░░ 55%  ✗（劣化！增益不平坦+滤波器累积+激光器老化）
  λ4: ██████░░ 80%  ✓（临界）

  → 只有 λ3 触发告警/重路由
  → λ1/λ2/λ4 继续正常工作
```

### 四、为什么不是"同批次都有问题"？

|因素|为什么影响不均匀|
| ------| --------------------------------------------------|
|**增益不平坦**|不同波长在 EDFA 增益谱中位置不同 → 放大倍数不同|
|**色散残余**|补偿针对中心波长优化 → 边缘波长残余更大|
|**非线性效应**|波长间隔不同 → 受 FWM/SRS 影响程度不同|
|**激光器个体差异**|每个激光器是独立器件 → 老化/温漂各不相同|
|**WSS 偏差**|每个波长通过 WSS 的损耗略有不同 → 多站累积|
|**滤波器级联**|微小偏差经过多站放大 → 特定波长累积劣化|

**核心原因一句话**：光器件（放大器、滤波器、激光器）对不同波长的响应**不是完全一致的**，这些微小差异经过多个网段**累积放大**后，就导致某些波长"扛不住"而其他波长"没问题"。

### 五、工程上的应对措施

|措施|解决什么问题|原理|
| ------| ----------------------| ------------------------------------------------|
|**增益平坦滤波器（GFF）**|EDFA 增益不平坦|在放大器内加滤波器，压低中心增益、提升边缘|
|**预加重**|多段累积功率不均|发送端故意让边缘波长发更大功率，补偿放大器不均|
|**动态增益均衡（DGE）**|ROADM 站点间功率不均|每站自动调节各波长功率|
|**波长定期巡检**|激光器老化/温漂|OPM 持续监控各波长 OSNR，提前预警|
|**波长轮换**|特定波长长期劣化|将劣化波长的业务迁移到其他波长|

---

### 六、一句话总结

> **合波后各波长&quot;命运不同&quot;的根本原因**：光放大器、滤波器、激光器等器件对不同波长的响应**天然不一致**——增益有高有低、损耗有大有小、老化有快有慢，这些微小差异经过多个网段**逐级累积**，最终导致某些波长劣化超标而其他波长仍然正常。这就是为什么 OTN 需要**逐波独立监控**（而非只看合波总功率），也是单波长能独立触发重路由的物理基础。

## OTN 各层保护场景详解

### 一、总览：三层保护各管什么

```text
OTN 分层保护模型：

┌─ ODUk 层保护 ──────────────────────────────┐
│  管"业务"：单个电通道（单个客户业务）         │
│  场景：电层故障、时隙错误、端到端业务保护      │
│                                             │
│  ┌─ OCH 层保护 ────────────────────────────┐│
│  │  管"波长"：单个光通道（单个波长）          ││
│  │  场景：单波劣化、波长冲突、光通道中断      ││
│  │                                         ││
│  │  ┌─ OMS 层保护 ───────────────────────┐ ││
│  │  │  管"光纤"：整段合波段（所有波长）     │ ││
│  │  │  场景：光纤断裂、光放故障            │ ││
│  │  └────────────────────────────────────┘ ││
│  └─────────────────────────────────────────┘│
└─────────────────────────────────────────────┘
```

---

### 二、OMS 层保护场景

#### 保护对象：整根光纤（所有波长一起保护）

#### 场景 1：光纤断裂（最典型）

```text
正常：
  A ════════ B（80波全在工作光纤上）
  A ─ ─ ─ ─ B（保护光纤 standby）

挖掘机挖断光纤：
  A ═══ ✗ ═══ B ← 断了！80波全部丢失

倒换：
  A ════════ B ← 80波全部切到保护光纤
  < 50ms，业务无感知

特点：如果不做 OMS 保护，80 波业务全部中断
      做了 OMS 保护，一次倒换恢复所有业务
```

#### 场景 2：光放大器（OA）板故障

```text
正常：
  A站 BA（功放）──光纤──▶ B站 PA（前放）

BA 板硬件故障：
  → 工作光纤上所有波长功率骤降
  → OMS 检测到 LOS/功率劣化
  → 整纤倒换到保护光纤（保护光纤有自己的 OA）

特点：OA 是"一坏坏一片"，OMS 保护一次恢复所有波长
```

#### 场景 3：合波器/分波器故障

```text
正常：
  各波长 → MUX（合波器）→ 合波信号 → 光纤

MUX 故障：
  → 合波输出异常，所有波长丢失
  → OMS 保护倒换

特点：MUX/DEMUX 故障影响所有波长，只有 OMS 能保护
```

#### OMS 保护适用场景总结

|场景|特点|为什么选 OMS|
| -------------------------------------| -----------------------| ------------------------|
|骨干链型段（A→B 只有一条光纤路由）|光纤断裂风险|简单可靠，无需 SDN|
|长距无中继段|光纤故障影响大|\< 50ms 倒换|
|管道/杆路共用段|施工挖断风险高|物理路由不同的备用光纤|
|存量 SDH 段改造|已有 1+1 光纤保护习惯|运维人员熟悉|

---

### 三、OCH 层保护场景

#### 保护对象：单个波长通道

#### 场景 1：单波劣化（最常见）

```text
正常：
  A→B→C→D，λ1~λ80 全部正常

运行一段时间后：
  λ37 pre-FEC BER 逐渐升高（激光器老化）
  其他 79 波正常

OCH 保护：
  → 只重路由 λ37，分配新波长走新路径
  → 其他 79 波完全不受影响
  → 如果做 OMS 保护，会导致 80 波全部无意义倒换

特点：精准打击，只处理有问题的波长
```

#### 场景 2：环网波长保护（OCH SPRing）

```text
环网拓扑：
  A ──── B
  │      │
  D ──── C

业务：A→C 的 λ1

工作路径（东向）：A → B → C（λ1）
保护路径（西向）：A → D → C（λ1）

B→C 段光纤断：
  → λ1 工作路径中断
  → OCH SPRing 倒换：λ1 走西向 A→D→C
  → 只有 λ1 受影响，其他波长正常

特点：环网中最常用的波长级保护
```

#### 场景 3：中间节点故障

```text
路径：A → B → C → D（λ1）

B 站掉电：
  → λ1 穿通失败（B 站无法处理 λ1）
  → OCH 保护：λ1 重路由到 A→E→D（绕过 B 站）
  → 其他经过 B 站的波长也各自重路由

特点：OMS 保护无法处理节点故障（节点不工作≠光纤断）
      OCH 保护可以绕过故障节点
```

#### 场景 4：波长冲突需要调整

```text
场景：网络优化/扩容时

原状态：
  路径1：A→B→C，使用 λ5
  路径2：D→B→E，使用 λ5（B 站两侧不同方向，不冲突）

扩容后需要：
  新增路径 D→B→C，但 λ5 在 B→C 段已被路径1占用
  
OCH 层操作：
  → 将路径1的 λ5 迁移到 λ7
  → 释放 λ5 给新业务
  → 迁移过程中路径1短暂中断（可通过 ODUk 保护做到无损）

特点：OCH 层支持波长动态调整，OMS 层做不到
```

#### OCH 保护适用场景总结

|场景|特点|为什么选 OCH|
| --------------| --------------------| ----------------------------|
|Mesh 网状网|多路径可选|可逐波重路由，资源利用率高|
|环网承载|东/西向保护|OCH SPRing 是环网标准方案|
|单波劣化|个别波长 OSNR 不足|精准处理，不影响其他波|
|节点故障|中间站掉电/故障|可绕过故障节点|
|波长动态调度|扩容/优化|支持波长迁移和重分配|

### 四、ODUk 层保护场景

#### 保护对象：单个电通道（单个客户业务）

#### 场景 1：端到端业务保护（最典型）

```text
业务：A站 100GE → D站

工作 ODUk：A→B→C→D（时隙 TS3）
保护 ODUk：A→E→F→D（时隙 TS3）

C→D 段 λ1 的 TS3 时隙误码：
  → ODUk 层检测到 PM-BIP-8 超标
  → 倒换到保护 ODUk（A→E→F→D）
  → 100GE 业务无感知

特点：
  即使光层（OCH/OMS）都正常
  电层的时隙级故障也能保护
  这是 OMS/OCH 保护不了的
```

#### 场景 2：支路盘/线路盘故障

```text
业务：A站支路盘1 → D站

工作路径：A站支路盘1 → 交叉盘 → A站线路盘1 → ... → D站
保护路径：A站支路盘1 → 交叉盘 → A站线路盘2 → ... → D站

A站线路盘1 故障：
  → 该盘上所有 ODUk 通道中断
  → ODUk SNCP 倒换：交叉盘将业务切到线路盘2
  → 业务恢复

特点：设备内部板卡故障
      OMS/OCH 层看不到（光口还在发光）
      只有 ODUk 层能检测和保护
```

#### ODUk 保护适用场景总结

|场景|特点|为什么选 ODUk|
| ----------------| -------------------| ---------------------------|
|端到端业务保护|业务级 SLA 要求|最细粒度，业务独立保护|
|设备板卡故障|支路盘/线路盘故障|OMS/OCH 检测不到|
|跨厂商互通|多厂商混合组网|ODUk 开销标准化，跨域互通|
|差异化保护|不同业务不同 SLA|可按需配置，精细控制|
|电层时隙故障|特定时隙误码|只保护故障时隙的业务|

## OTN 各层 × 各保护类型 完整矩阵

### 一、总览矩阵

|保护层级|1+1 保护|1:1 保护|重路由|多路径预置|
| ----------| -------------------| -------------------| ---------------------| ---------------------|
|**OMS 层**|✓ 整纤双发选收|✓ 整纤主备切换|✗ 不适用|✗ 不适用|
|**OCH 层**|✓ 单波双发选收|✓ 单波主备切换|✓ 单波动态重路由|✓ 单波多路径预置|
|**ODUk 层**|✓ 单业务双发选收|✓ 单业务主备切换|✓ 单业务动态重路由|✓ 单业务多路径预置|

### 二、OMS 层保护

#### OMS 1+1（整纤双发选收）

```text
发送端：
  业务（所有波长）──┬──▶ 工作光纤 ═══▶ B
                   └──▶ 保护光纤 ─ ─▶ B

接收端：
  工作光纤 ──▶ 选收开关 ──▶ 业务输出
  保护光纤 ──▶ 选收开关
                └─ 工作正常 → 选工作
                └─ 工作故障 → 切保护（< 50ms）

适用场景：
  ✓ 链型骨干段（A→B），担心光纤断
  ✓ 简单可靠，配置简单
  ✗ 不适合环网/Mesh（浪费光纤资源）
```

#### OMS 1:1（整纤主备切换）

```text
正常状态：
  业务（所有波长）──▶ 工作光纤 ═══▶ B
  低优先级业务 ───▶ 保护光纤 ─ ─▶ B  ← 保护光纤不空闲！

故障时：
  工作光纤断 → 低优先级业务让出 → 高优先级业务切到保护光纤

适用场景：
  ✓ 链型段保护，同时想利用保护光纤传低优先级业务
  ✓ 资源利用率比 1+1 略高
```

#### OMS 为什么不支持重路由/预置？

```text
OMS 保护的是"整段光纤"——物理层面的光纤链路
→ 光纤断了就是断了，没有"算新路"的概念
→ 只有两条光纤（工作+保护），没有"多条路径"可选
→ 所以 OMS 层只有 1+1 和 1:1，没有重路由和预置

重路由和预置需要 SDN 控制器参与波长级调度
→ 这是 OCH 层和 ODUk 层的事
```

### 三、OCH 层保护

#### OCH 1+1（单波双发选收）

```text
发送端（A站）：
  OCH-λ1 ──┬──▶ 路径1（A→B→C）──▶ D站
            └──▶ 路径2（A→E→F）──▶ D站

接收端（D站）：
  路径1 ──▶ 选收开关 ──▶ 业务输出
  路径2 ──▶ 选收开关
              └─ 路径1正常 → 选路径1
              └─ 路径1劣化 → 切路径2（< 50ms）

特点：
  → 只保护 λ1，λ2/λ3 不受影响
  → 两条路径同时占用波长资源
  → 适用于高可靠单波长业务
```

#### OCH 1:1（单波主备切换）

```text
正常状态：
  OCH-λ1 ──▶ 路径1（A→B→C）──▶ D站  ← 工作
  OCH-λ2 ──▶ 路径2（A→E→F）──▶ D站  ← 保护（可传低优先级业务）

故障时：
  路径1的 λ1 故障 → λ1 切到路径2（抢占 λ2 位置）

特点：
  → 保护波长平时可传低优先级业务
  → 故障时高优先级抢占
  → 资源利用率比 1+1 高
```

#### OCH 重路由（单波动态重路由）

```text
正常状态：
  OCH-λ1：A → B → C → D

λ1 劣化（B→C 段）：
  SDN 控制器检测到 λ1 pre-FEC BER 超标
  → 实时算路：排除 B→C 段
  → 新路径：A → E → F → D
  → 新波长：λ7（避开冲突）
  → 秒级~分钟级恢复

特点：
  → 无需提前预留保护资源
  → 按需分配，资源利用率最高
  → 需要 SDN 控制器在线
  → 恢复时间取决于算路速度
```

#### OCH 多路径预置（单波多路径预置）

```text
预配置：
  路径1（主用）：A → B → C → D，λ1
  路径2（备选1）：A → E → F → D，λ7
  路径3（备选2）：A → B → G → D，λ3

故障切换：
  路径1故障 → 秒级切到路径2
  路径2也故障 → 秒级切到路径3
  全部故障 → 触发动态重路由

特点：
  → 切换速度快（秒级，无需算路）
  → 需要预占多个波长资源
  → 适用于高可靠 + Mesh 拓扑
```

### 四、ODUk 层保护

#### ODUk 1+1（单业务双发选收）

```text
发送端（A站交叉盘）：
  ODUk（某业务）──┬──▶ 时隙TS1-路径1（A→B→C→D）──▶ D站
                   └──▶ 时隙TS1-路径2（A→E→F→D）──▶ D站

接收端（D站交叉盘）：
  路径1 ──▶ 选收开关 ──▶ 业务输出
  路径2 ──▶ 选收开关

特点：
  → 粒度最细（单个 ODUk 业务）
  → 可跨不同波长保护（路径1走λ1，路径2走λ2）
  → 同一波长内不同业务独立保护
```

#### ODUk 1:1（单业务主备切换）

```text
正常：
  ODUk-业务1 ──▶ TS1-路径1（工作）
  ODUk-业务2 ──▶ TS1-路径2（保护，平时传低优先级）

故障：
  路径1故障 → 业务1 切到路径2

特点：
  → 保护时隙可复用（平时传低优先级）
  → 适用于差异化 SLA 场景
```

#### ODUk 重路由

```text
正常：
  ODUk：A → B → C → D（λ1 的 TS1 时隙）

故障（B→C 段 λ1 劣化，但 λ2 正常）：
  SDN 控制器：
  → 只重路由故障的 ODUk
  → 新路径：A → E → F → D
  → 新波长：λ2 的 TS3 时隙
  → 其他 ODUk（λ1 上的其他业务）不受影响

特点：
  → 粒度最细，只影响故障业务
  → 可跨波长、跨路径迁移
  → 需要 SDN 控制器支持 ODUk 级调度
```

#### ODUk 多路径预置

```text
预配置：
  路径1：A→B→C→D，λ1-TS1
  路径2：A→E→F→D，λ2-TS3
  路径3：A→B→G→D，λ3-TS2

故障切换：
  路径1故障 → 秒级切到路径2（换波长+换时隙）
  路径2也故障 → 秒级切到路径3

特点：
  → 最细粒度的快速保护
  → 金融/电力等高 SLA 场景首选
  → 资源消耗最多（每条路径预占时隙）
```

### 五、完整场景对照表

|故障场景|OMS 层应对|OCH 层应对|ODUk 层应对|
| ----------| ----------------------------------| ---------------------------------| ----------------------------------|
|**光纤断裂**|OMS 1+1 切保护光纤（\< 50ms）|如果 OMS 没配，OCH 重路由|如果 OMS/OCH 都没配，ODUk 重路由|
|**单波劣化**|无法处理（整纤正常）|OCH 1+1 切备用路径 / OCH 重路由|ODUk 1+1 切备用时隙|
|**节点故障**|无法处理（只保护光纤）|OCH 重路由绕开故障节点|ODUk 重路由绕开故障节点|
|**板卡故障**|无法处理|OCH 重路由|ODUk 重路由（换板卡/换时隙）|
|**信号劣化（SD）**|OMS 1+1 切保护光纤|OCH 1+1 切备用 / 重路由|ODUk 1+1 切备用 / 重路由|

### 六、多层保护叠加方案

```text
高可靠网络典型配置：

┌──────────────────────────────────────────────────────────┐
│ 第1层：OMS 1+1（整纤保护）                                │
│ → 应对光纤断裂，< 50ms 倒换                               │
│ → 所有波长一起保护，最简单最快                              │
├──────────────────────────────────────────────────────────┤
│ 第2层：OCH 多路径预置（单波保护）                           │
│ → 应对单波劣化/节点故障，秒级切换                           │
│ → 预置3条路径，按优先级切换                                 │
├──────────────────────────────────────────────────────────┤
│ 第3层：ODUk 1+1（单业务保护）                              │
│ → 应对板卡故障/电层异常，< 50ms 倒换                       │
│ → 金融级业务的最后一道保险                                  │
├──────────────────────────────────────────────────────────┤
│ 第4层：ODUk 重路由（兜底恢复）                              │
│ → 所有预置路径都不可用时，SDN 动态算路                      │
│ → 最后的恢复手段                                           │
└──────────────────────────────────────────────────────────┘

故障场景推演：
  光纤断 → OMS 1+1（50ms）恢复 ✓
  OMS 保护光纤也断 → OCH 预置路径2（秒级）恢复 ✓
  预置路径2节点故障 → OCH 预置路径3（秒级）恢复 ✓
  所有预置路径故障 → ODUk 1+1（50ms）兜底 ✓
  全部失效 → ODUk 重路由（分钟级）尽力恢复
```

### 七、一句话总结

> **OMS 层**只有 1+1/1:1（整纤保护），因为光纤断了只能切光纤，没有"算路"概念；**OCH 层**四种全支持（1+1/1:1/重路由/预置），是保护的主战场；**ODUk 层**也四种全支持，粒度最细，保护单个业务。实际网络中按需叠加——OMS 保光纤、OCH 保波长、ODUk 保业务，从毫秒到分钟级全覆盖，确保"永不中断"。

## OTN 各层保护：Data Link 与 TE Link 属性详解

### 一、为什么需要 Data Link 和 TE Link？

```text
ASON/SDN 控制器要算路，首先需要"理解"网络拓扑：

  控制器看到什么？
  
  不是：一堆设备和光纤的物理连接
  而是：抽象的"链路"（Link）——带属性的逻辑连接

  两种关键链路类型：
  · TE Link（Traffic Engineering Link）：用于算路的链路抽象
  · Data Link：承载实际业务的链路实例

  类比：
  · TE Link = 地图上标注的"道路"（有车道数、限速、通行状态）
  · Data Link = 某辆车正在走的"那条路"（有实际占用情况）
```

---

### 二、TE Link（流量工程链路）

#### 2.1 TE Link 是什么

**TE Link（Traffic Engineering Link）**  是控制器用于**路由计算**的链路抽象——把物理资源抽象为带属性的"可算路链路"。

```text
物理层：
  A站 ──────光纤────── B站
  
控制器抽象为 TE Link：
  TE Link {
    源端口：A站-线路盘1-西向
    宿端口：B站-线路盘1-东向
    带宽容量：96 × 100G = 9.6T（96 波 × 单波 100G）
    已用带宽：40 × 100G = 4T
    剩余带宽：56 × 100G = 5.6T
    代价（Cost）：100km × 0.25dB/km = 25dB
    OSNR 余量：22dB
    状态：可用
    保护类型：OMS 1+1
    ...
  }
```

#### 2.2 TE Link 的核心属性

|属性|说明|各层取值|
| ------| ---------------------| -------------------------------------------------------------------------|
|**Link ID**|链路唯一标识|每层独立编号|
|**源/宿端口**|链路两端端口|OMS\=光放口，OCH\=线路口，ODUk\=交叉端口|
|**带宽容量**|链路最大承载能力|OMS\=总波数×单波速率，OCH\=单波速率，ODUk\=时隙数×单时隙速率|
|**已用/剩余带宽**|资源占用情况|实时统计|
|**代价值（Cost）**|算路时的权重|通常\=距离/OSNR余量/跳数|
|**OSNR 余量**|信号质量裕量|光层关键属性|
|**保护类型**|链路保护配置|1+1/1:1/无保护|
|**保护状态**|当前是否在工作/保护|工作/保护/失效|
|**链路状态**|是否可用|正常/降级/失效|
|**共享风险组（SRLG）**|同缆/同沟风险标识|用于路由分离约束|

---

### 三、Data Link（数据链路）

#### 3.1 Data Link 是什么

**Data Link** 是**实际承载业务的链路实例**——当一条业务连接建立后，它在某条 TE Link 上占用的资源就形成一个 Data Link。

```text
TE Link（抽象链路）：
  A→B 光纤，总容量 96 波

Data Link（业务实例）：
  Data Link 1：λ1（192.1THz），100G，A→B，承载 100GE-业务1
  Data Link 2：λ2（192.2THz），100G，A→B，承载 10GE-业务2
  Data Link 3：λ3（192.3THz），200G，A→B，承载 200GE-业务3
  ...

  TE Link = "这条路"
  Data Link = "路上跑的每一辆车"
```

#### 3.2 Data Link 的核心属性

|属性|说明|
| ------| -------------------------|
|**Data Link ID**|业务链路唯一标识|
|**关联 TE Link**|该业务在哪条 TE Link 上|
|**占用资源**|具体占用了哪个波长/时隙|
|**业务类型**|OCH/ODUk/OMS|
|**带宽**|实际占用带宽|
|**保护角色**|工作 / 保护|
|**源/宿业务端口**|业务的源和宿|
|**状态**|激活 / 去激活 / 故障|

#### 三层 Data Link 属性对比

|对比维度|OMS Data Link|OCH Data Link|ODUk Data Link|
| ----------| ---------------------------| ------------------------------| ---------------------------|
|**代表什么**|一段光纤的合波段|一个端到端波长通道|一个电层业务通道|
|**粒度**|最粗（整段光纤）|中（单个波长）|最细（单个时隙）|
|**核心资源**|波长列表（哪些空闲）|频谱槽位 + 调制格式|时隙编号 + 带宽|
|**路由信息**|两个端点 + 光纤参数|端到端路径 + 各段 OSNR|端到端路径 + 各站交叉方式|
|**保护信息**|OMSP 类型 + 工作/保护光纤|OCH 保护类型 + 工作/保护路径|SNCP 类型 + 工作/保护通道|
|**质量信息**|光功率 + 段 OSNR|端到端 OSNR + FEC BER|TCM-BIP-8 + 时延|
|**SLA 信息**|无|无（或波长级）|有（业务级 SLA）|
|**控制器用途**|波长资源管理|波长分配 + 算路|时隙分配 + 业务编排|

### 六、TE Link 属性在算路中的作用

```text
SDN 控制器算路时如何使用 TE Link 属性：

业务请求：A→D，需要 200G

Step 1：收集所有 TE Link
  OMS 层：
    A-B：容量 38.4T，剩余 22.4T，Cost=25，状态=正常
    A-E：容量 38.4T，剩余 28T，Cost=18，状态=正常
    B-C：容量 38.4T，剩余 15T，Cost=20，状态=正常
    E-F：容量 38.4T，剩余 30T，Cost=15，状态=正常
    C-D：容量 38.4T，剩余 20T，Cost=22，状态=正常
    F-D：容量 38.4T，剩余 25T，Cost=12，状态=正常

Step 2：带宽约束过滤
  需要 200G → 所有 TE Link 剩余容量 > 200G ✓
  → 全部通过

Step 3：OSNR 约束过滤
  200G → DP-8QAM → 要求 OSNR ≥ 18dB
  路径1（A→B→C→D）：端到端 OSNR = 22dB ≥ 18dB ✓
  路径2（A→E→F→D）：端到端 OSNR = 26dB ≥ 18dB ✓

Step 4：波长资源检查
  路径1：A-B/B-C/C-D 共同空闲波长 = λ3,λ7,λ15
  路径2：A-E/E-F/F-D 共同空闲波长 = λ1,λ2,λ7,λ9

Step 5：代价最优选择
  路径1 Cost = 25+20+22 = 67
  路径2 Cost = 18+15+12 = 45 ← 更优！

Step 6：SRLG 检查
  路径1 和 路径2 是否共享 SRLG？
  → 无共享光缆 → 路由分离 ✓

Step 7：输出结果
  路径：A→E→F→D
  波长：λ1
  调制：DP-8QAM
  保护：OCH 1+1（保护路径 A→B→C→D，λ3）
```

### 七、各层 TE Link 属性对比总结

|属性|OMS 层 TE Link|OCH 层 TE Link|ODUk 层 TE Link|
| ------| ---------------------| ---------------------| ----------------------|
|**抽象对象**|光纤段（两站之间）|波长通道（端到端）|时隙通道（端到端）|
|**带宽单位**|波数 × 单波速率|单波速率|时隙数 × 单时隙速率|
|**关键资源**|波长（λ1\~λn）|频率/波长|时隙（TS1\~TSn）|
|**代价值**|光纤衰耗/距离|距离/OSNR/跳数|继承 OCH 层|
|**OSNR**|段 OSNR|端到端 OSNR|不直接关联|
|**保护属性**|OMS 1+1/1:1|OCH 1+1/重路由/预置|ODUk SNCP 1+1/重路由|
|**SRLG**|光缆段标识|继承 OMS 层|继承 OCH 层|
|**算路约束**|波长资源、光纤状态|波长连续性、OSNR|时隙可用性|

### 八、一句话总结

> **TE Link** 是控制器用于算路的**链路抽象**——把物理资源（光纤/波长/时隙）抽象为带带宽、代价、OSNR、保护类型、SRLG 等属性的逻辑链路，供 PCE 算路引擎使用；**Data Link** 是**业务实例**——实际占用 TE Link 上的具体资源（哪个波长、哪个时隙）。OMS 层 TE Link 关注光纤段容量和波长资源，OCH 层 TE Link 关注波长通道和 OSNR，ODUk 层 TE Link 关注时隙分配和电层通道状态。三层 TE Link 层层嵌套：OMS 承载多个 OCH，OCH 承载多个 ODUk，算路时自顶向下逐级检查资源可用性，最终完成端到端业务连接。

## OTN 各层保护：Data Link详解

### 一、Data Link 是什么

**Data Link（数据链路）**  是 SDN 控制器对传输网络中**每一段逻辑连接**的抽象建模——控制器通过维护各层 Data Link 实例来管理资源、计算路径、触发保护。

```text
SDN 控制器视角：
  不是看"设备"和"板卡"
  而是看"链路"和"连接"

  Data Link = 两个端口之间的一段逻辑连接
  · OMS Data Link：两个光放端口之间的光纤段
  · OCH Data Link：两个线路端口之间的波长通道
  · ODUk Data Link：两个交叉端口之间的电通道
```

### 四、ODUk Data Link 属性

#### 4.1 Data Link 定义

```text
ODUk Data Link = 两个交叉盘端口之间的电层业务通道

  A站交叉盘 ── λ1-TS1 ── B站 ── λ1-TS1 ── D站交叉盘
  │                                              │
  ODUk-A1 端口                              ODUk-D1 端口
  │                                              │
  └─────────── ODUk Data Link ───────────────────┘
```

#### 4.2 核心属性

|属性|含义|示例值|
| ------| -----------------| -----------------------------|

### 五、三层 Data Link 嵌套关系与各站总览

```text
三层 Data Link 嵌套：

  OMS Data Link（A→B）
  ├── OCH Data Link（A→B，λ1）
  │   ├── ODUk Data Link（A→B，λ1-TS1）
  │   ├── ODUk Data Link（A→B，λ1-TS2）
  │   └── ...
  ├── OCH Data Link（A→B，λ2）
  │   └── ...
  └── ...

  端到端 ODUk Data Link（A→D）跨越多个 OMS：
  ┌────────────────────────────────────────────────────┐
  │ ODUk Data Link（A→D，业务 10GE）                   │
  │                                                    │
  │ 底层承载：                                         │
  │ · OCH Data Link（A→D，λ1）                         │
  │   · OMS DL-1（A→B）+ OMS DL-2（B→C）+ OMS DL-3（C→D）│
  │ · 时隙：λ1-TS1                                     │
  │ · 保护：ODUk SNCP 1+1（保护路径 A→E→F→D）          │
  └────────────────────────────────────────────────────┘
```

#### 各站体现总览表

|站点角色|OMS Data Link|OCH Data Link|ODUk Data Link|
| ----------| ----------------------------| -------------------------| --------------------------|
|**源站**|发送光功率、光放配置、双发|调制发光、FEC配置、双发|交叉映射、时隙分配、双发|
|**中间站（光穿通）**|不适用（OMS 是点到点）|穿通光功率/OSNR 监控|完全透明（看不到）|
|**中间站（电穿通）**|不适用|开销监控（BER/SM）|开销监控（TCM/时隙）|
|**宿站**|收光功率、OSNR 监控、选收|接收检测、FEC解码、选收|解映射、误码检测、选收|

### 六、一句话总结

> **三层 Data Link 是 SDN 控制器管理 OTN 资源的核心模型**：OMS Data Link 管光纤段（光功率/波长资源/OSNR），OCH Data Link 管波长通道（调制/FEC/端到端 OSNR/BER），ODUk Data Link 管电层业务（时隙/SLA/TCM 误码）；三者嵌套——ODUk 承载在 OCH 上，OCH 承载在 OMS 上。**源站**负责发送和保护双发，**宿站**负责接收和保护选收判决，**中间站**在光穿通时对 OCH/ODUk "透明"（只监控光功率），在电穿通时可监控开销但不感知保护——保护始终是端到端的行为，中间站只是"路过"。
